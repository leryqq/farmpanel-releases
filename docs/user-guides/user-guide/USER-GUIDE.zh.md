# 1. 简介

## FarmPanel 是什么

**FarmPanel** 是一款 Windows 桌面应用，帮助你在单个窗口中管理众多 Steam 账号和 Counter-Strike 2 客户端。你无需再手动打开数十个 Steam 窗口、逐一盯着它们、并重启那些卡死的窗口，而是可以从一个清晰的面板集中管理整个账号农场。

FarmPanel 会启动客户端、将账号彼此隔离、实时监视其状态，并在发生故障后自动恢复它们。

> **重要提示。** FarmPanel **不是机器人，也不是自动搬砖工具**。它不会替你游玩，也不会模拟游戏内的操作。它管理的是游戏*周边*发生的一切：启动客户端、大厅邀请、故障后恢复，以及每个账号的实时可见性。所有游戏内操作都由真人完成。

## 它解决什么问题

如果你拥有不止一个账号，这套日常想必并不陌生：

- 你得启动数十个 Steam 与 CS2 客户端；
- 每个账号必须彼此独立运行，互不干扰；
- 手动组建大厅、发送邀请既慢又累；
- CS2 崩溃后必须及时发现并重启；
- 很难分清谁已经在对局中、谁还卡在加载。

FarmPanel 消除了这套日常，把每一项操作都汇集到一个应用中。

## 它面向谁

本应用面向任何需要集中管理众多 Steam 与 CS2 账号的人——从寥寥数个到数百个——并提供自动启动、实时监控以及故障后可靠恢复。

## 你可以做什么

- 将所有账号集中一处，快速找到需要的那个。
- 逐个或一次性启动和停止账号。
- 将每个账号隔离在各自受保护的环境（一个 sandbox）中。
- 组建账号的队伍（party），让它们一起排队匹配。
- 实时监视计算机负载、进程健康状况和崩溃。
- 在崩溃后或应用关闭后自动恢复账号。
- 使用预设布局在你的显示器上排列 CS2 窗口。

# 2. 开始之前

## 系统要求

| 项目 | 最低 | 推荐 |
|---|---|---|
| 操作系统 | Windows 10 或 11（64 位） | Windows 10 / 11（64 位） |
| 内存 | 8 GB | 32 GB |
| 磁盘 | 任意 | SSD |
| 同时运行的账号 | 2 | 4–10 个 CS2 账号 |
| 屏幕分辨率 | 工作区宽度至少 1280 像素 | Full HD（1920×1080）或更高 |

## 需提前准备的东西

- **FarmPanel 安装程序**——一个名为 `Setup.exe` 的文件，从官方下载页面下载。
- **一个许可密钥**——随购买一同获得。它形如：`XXXX-XXXX-XXXX-XXXX-XXXX`（五组，每组四个字符）。
- **你的 Steam 账号信息**——用户名和密码，以及在使用时的 Steam Guard 验证码。你可以逐个输入，也可以从文件导入一份列表。
- **一个网络连接**——首次启动激活许可时需要，之后 Steam 与 CS2 的运行也需要它。

## 权限

- 安装**不需要管理员权限**——应用仅为你的用户账户安装。
- 首次运行安装程序时，Windows 可能会弹出蓝色的 **SmartScreen** 窗口（“Windows protected your PC”）——这是针对新程序的常规提示。点击 **More info**，然后 **Run anyway**。
- 应用可能需要网络访问（用于 Steam）以及对 Windows 防火墙规则的访问。如果出现防火墙提示，请允许访问。

## 你的数据存储在哪里

用户名和密码通过 Windows 内置保护加密，且**仅存储在你的计算机上**。它们从不以明文保存，也从不发送到任何地方。

# 3. 首次启动

以下是从安装到面板可用的完整路径。请按顺序执行各步骤。

## 步骤 1. 安装应用

1. 从下载页面下载 `Setup.exe` 安装程序。
2. 双击 `Setup.exe` 文件。
3. 如果出现蓝色的 **SmartScreen** 窗口（“Windows protected your PC”），点击 **More info**，然后 **Run anyway**。这是针对新程序的常规提示，并非错误。
4. 等待安装完成。无需管理员权限——安装程序会检查你的系统并准备好一切。

**接下来会发生什么。** 桌面和开始菜单中会出现一个 FarmPanel 图标。

![Setup.exe 安装程序窗口](../images/setup-installer.png)

## 步骤 2. 打开应用

双击桌面上的 **FarmPanel** 图标。

**你会看到什么。** 首次启动时，由于许可尚未激活，会打开 **Activation Wizard**（激活向导）。主界面只有在成功激活后才会出现。

## 步骤 3. 激活你的许可

激活窗口会引导你逐步完成。

1. 在输入框中键入或粘贴你的许可密钥。若要从剪贴板粘贴，点击 **Paste from clipboard**。
2. 你键入时，应用会检查密钥格式。格式正确后，激活按钮即变为可用。
3. 点击 **Activate**。

**接下来会发生什么。** 应用会联系许可服务器并验证密钥。这需要几秒钟——你会看到 **Activating** 状态。

**成功的标志。** 激活窗口关闭，应用主界面（**Dashboard**）打开。你的许可已激活——之后的启动无需再次输入密钥。

> **若激活失败**，应用会显示清晰的提示并告诉你该怎么做。常见情形已在 [10. 错误与故障排除](#10-错误与故障排除) 中说明。

![许可激活窗口](../images/license-activation.png)

## 步骤 4. 检查基本设置

首次启动账号之前，值得先检查一下你的设置。

1. 点击左侧面板中的 **Settings**，或按 `Ctrl+,`。
2. 打开 **Sandboxes** 部分，如有需要，为 sandbox 选择一个文件夹。
3. 也可打开 **Appearance**，选择主题（**System / Dark / Light**）和界面密度。

设置会自动保存：每次更改后都会短暂出现 **Saved** 通知。

## 步骤 5. 准备就绪

现在你可以添加账号并启动第一批农场了。做法参见 [5. 核心工作流程](#5-核心工作流程)。

**一切正常的标志。** 窗口底部的栏（状态栏）会显示一份汇总：账号数量、活动进程数以及当前应用版本。

## 4.1. Command Bar（顶部栏）

**用途。** 横贯窗口顶部的固定条带。它容纳导航、全局搜索和通知。

**位置。** 窗口最上面一行。

**主要元素（从左到右）：**

- **汉堡按钮（☰）**——折叠和展开侧边栏。快捷键 `Ctrl+B`。
- **徽标**——点击它可返回主界面（**Dashboard**）。
- **面包屑（Breadcrumbs）**——显示你当前所在位置，例如 `Accounts › alex_42 › Events`。点击任一段可跳转到那里。
- **搜索 / 命令面板**——位于中间。按 `Ctrl+K` 打开命令面板（见下文）。
- **通知徽标**——带计数的图标（例如 `⚠ 3`）。点击它可打开通知中心。

**何时使用。** Command Bar 始终触手可及：用于在界面间快速跳转、按用户名搜索账号，或无需鼠标即可运行命令。

### Command Palette

随时按 `Ctrl+K` 打开命令面板——一个可搜索应用中每个操作与对象的搜索框。

1. 开始键入某个命令、界面、账号用户名或工作流程的名称。
2. 列表会缩小到匹配的结果。用 `↑` `↓` 在其中移动。
3. 按 `Enter` 运行所选项。

**它为何有用。** 命令面板是无需记住按钮位置便能找到任何东西的最快方式。

![打开的命令面板](../images/command-palette.png)

## 4.2. Sidebar（侧边栏）

**用途。** 应用的主导航。

**位置。** 位于左侧，占满窗口整个高度。

**各部分（从上到下）：**

| 图标 | 部分 | 显示内容 |
|---|---|---|
| ▤ | **Dashboard** | 整个农场的概览 |
| 👥 | **Accounts** | 所有账号列表（主工作界面） |
| ⚙ | **Workflows** | 自动启动方案及其进度 |
| ⚔ | **Matchmaking** | 队伍与匹配搜索 |
| 📈 | **Monitoring** | 计算机负载与进程健康状况 |
| 📜 | **Logs** | 事件日志 |
| ▣ | **Layouts** | 在显示器上排列 CS2 窗口 |
| ▦ | **Sandboxes** | Sandbox（隔离环境） |
| ⚙ | **Settings** | 应用设置 |
| ? | **Help** | 帮助 |

某些部分会显示一个计数（例如账号数量），或在有活动时显示一个实时圆点。

**主要操作：**

- 点击某个部分即可打开它。你也可以使用 `Ctrl+1`…`Ctrl+8`。
- 折叠按钮（或 `Ctrl+B`）可将面板收缩为图标，以腾出空间。

**提示。** 在各部分之间切换会保留你的状态——筛选、选择和滚动位置。当你返回某个界面时，会发现它与你离开时一模一样。

![包含所有部分的侧边栏](../images/sidebar.png)

## 4.3. Status Bar（状态栏）

**用途。** 窗口底部一条细栏，快速汇总整个农场的状态。

**位置。** 窗口最下面一行。

**显示内容（示例）：**

```
[env: PROD] | ● 412 accounts (238 running) | ▶ 18 workflows | ◎ 7 matches | CPU 42% RAM 71% | ⚠ 3 errors | 14:32:08 | v1.0.1
```

- 存在多少账号，以及当前有多少在运行；
- 有多少工作流程和活动对局正在进行；
- 处理器和内存负载；
- 错误数量（点击可打开通知中心）；
- 时间和应用版本。

**何时使用。** 瞥一眼状态栏，一秒钟便能判断是否一切正常。

## 4.4. Dashboard 界面

**用途。** 单一的概览界面。它在几秒内回答：有多少账号在线、有多少工作流程正在运行或已失败、是否有匹配活动、是否有崩溃，以及计算机负载如何。

**位置。** 侧边栏的第一个部分。启动后随即打开。

**主要区域：**

- **KPI strip**——顶部五张卡片：**Accounts**、**Workflows**、**Matches**、**Errors**、**System**。每张卡片显示一个主要数字和一张迷你图表。点击卡片可跳转到相应界面。
- **Live Activity Feed**——运营事件的实时流。使用暂停按钮（或 `Space` 键）暂停滚动。
- **Account State Heatmap**——一个网格，其中每个账号是一个彩色单元格。颜色反映其状态。悬停可查看用户名和状态；点击可跳转到该账号。
- **Active Workflows / Matchmaking Queue / Sandboxes**——三块图块，分别汇总工作流程、匹配队列和 sandbox。
- **Failures & Crashes**——最近一小时内近期错误和崩溃的表格。

**典型用法。** 早上打开 **Dashboard** 一眼掌握农场概况，然后前往需要关注的地方。

**提示。**
- 各项指标会自动刷新。若要强制完整刷新，按 `F5`。
- 如果 **Errors** 卡片或失败表格中有任何红色高亮，请从那里开始排查。

![带 KPI strip 和活动流的 Dashboard](../images/dashboard-screen.png)

## 4.5. Accounts 界面

**用途。** 主工作界面。你在这里存储账号、找到所需账号，并启动和停止它们。

**位置。** 侧边栏的第二个部分（`Ctrl+2`）。

**主要区域：**

- **工具栏**——**Add Account**、**Import**、**Export** 和 **Refresh** 按钮，搜索框、筛选器和视图控件。
- **账号表格**——包含以下列的所有账号列表：状态、用户名、昵称、段位、工作流程、sandbox、标签、上次登录时间等。
- **Details Pane（详情窗格）**——位于右侧。显示所选账号的详情。用 `Ctrl+\` 显示或隐藏它。

**你可以做什么：**

- 逐个添加账号或导入一份列表。
- 搜索和筛选账号。
- 启动、停止和重启单个账号或同时多个账号。
- 将账号绑定到 sandbox 并分配工作流程。
- 查看详细的账号卡片：数据、历史、事件和日志。

**典型用法。** 在表格中选择你需要的账号，然后对它们执行操作——通过工具栏、右键菜单（右键单击）或键盘快捷键。

详细的分步说明见 [5. 核心工作流程](#5-核心工作流程)。

![带表格和详情窗格的 Accounts 界面](../images/accounts-screen.png)

### 账号详情窗格（Details Pane）

表格右侧会为所选账号显示一张卡片，包含以下标签页：

| 标签页 | 显示内容 |
|---|---|
| **Overview** | 核心数据、sandbox 绑定、所分配的工作流程、标签、关键日期和操作按钮 |
| **Inventory** | 账号库存：物品数量和价值 |
| **Workflow** | 所分配方案的当前状态及其当前步骤 |
| **Events** | 该账号的近期事件 |
| **Logs** | 筛选至该账号的事件日志 |
| **History** | 更改历史：创建、编辑、重命名、sandbox 重新绑定 |

**Overview** 标签页底部有一组按钮：**Start**、**Stop**、**Restart**、**Pause**，以及 **Edit account** 和 **Delete**。最相关的操作会被高亮：账号停止时高亮 **Start**，运行时高亮 **Stop**。

## 4.6. Workflows 界面

**用途。** 管理自动启动方案并观察其运行。

**位置。** 侧边栏的第三个部分（`Ctrl+3`）。

**什么是工作流程。** 工作流程是应用为某个账号执行的一系列预定义步骤：登录 Steam、启动 CS2 等等。同一方案始终以相同方式运行，因此结果是可预测的。

- **Definition**——方案模板：一组步骤。
- **Instance**——某个 definition 针对特定账号的一次运行。

**主要区域：**

- **左侧**——definition（模板）及其版本的列表。
- **中间**——正在运行的 instance 表格：哪个方案、针对哪个账号、处于哪一步、重试了多少次、何时开始。
- **右侧**——所选 instance 的详情（**Overview**、**State Machine**、**Steps**、**Logs**、**Retries** 标签页）。
- **底部**——可折叠的事件时间线，展示可见 instance 的情况（`Ctrl+T`）。

**何时使用。** 来这里查看每个账号的启动处于哪一步、暂停或重启某个方案，或弄清为何某件事未能完成。

![带三个窗格的 Workflows 界面](../images/workflows-screen.png)

## 4.7. Matchmaking 界面

**用途。** 组建账号的队伍，让它们一起排队匹配。

**位置。** 侧边栏的第四个部分（`Ctrl+4`）。

**关键概念：**

| 术语 | 含义 |
|---|---|
| **Party** | 一起搜索对局的一组账号 |
| **Quorum** | 所有队伍成员均已登录、在队列中且不在对局中 |
| **Queue** | 等待对局：位置、区域、模式 |
| **Match Found** | Steam 找到了对局。应用会自动为所有成员确认准备就绪——你无需做任何事 |
| **Desync** | 成员处于不一致状态（例如某人掉出了队列） |

**主要区域：**

- **左侧**——各队伍及其状态的列表（quorum、desync、match found、空闲）。
- **右侧**——所选队伍的详情：成员、其状态、队列位置、网络延迟、sandbox。
- **底部**——近期匹配事件的时间线。

**何时使用。** 你在这里组建 2–5 个账号的队伍并让它们排队。找到对局时，应用会自动为所有成员确认准备就绪。

![带队伍和详情的 Matchmaking 界面](../images/matchmaking-screen.png)

## 4.8. Monitoring 界面

**用途。** 实时监视计算机负载、进程健康状况和崩溃。

**位置。** 侧边栏的第五个部分（`Ctrl+5`）。

**主要区域：**

- **资源仪表**——**CPU**、**RAM**、**Disk**、**Net**，以及在可用时的 **GPU** 卡片，附当前数值和迷你图表。
- **Process Explorer**——所有正在运行的 Steam 与 CS2 进程的表格：每个属于哪个账号、消耗多少、已运行多久。
- **Crashes & Warnings**——近期故障的信息流。
- **Logs panel**——屏幕底部的一份日志，可折叠。

**时间控件。** 顶部可在 **Live**（实时）、**Last 1h / 24h** 和 **Custom**（自定义时段）之间切换。**Freeze** 按钮（`Ctrl+Space`）会冻结画面，方便你从容研究。

**何时使用。** 如果计算机开始变慢或崩溃变得频繁，打开 **Monitoring** 查看哪个进程在消耗资源、究竟是什么崩溃了。

> **提示。** 你可以用分离按钮将 **Monitoring** 界面在单独窗口中打开，并把它放到第二台显示器上。

![带仪表和进程列表的 Monitoring 界面](../images/monitoring-screen.png)

## 4.9. Logs 界面

**用途。** 所有应用事件的详细日志——如同一份正在发生之事的实时流。

**位置。** 侧边栏的第六个部分（`Ctrl+6`）。

**主要功能：**

- **级别筛选**——**Error**、**Warn**、**Info**、**Debug** 开关。默认显示错误、警告和信息消息。
- **来源筛选**——你可以将日志缩小到单个账号、工作流程或 sandbox。
- **搜索**——`Ctrl+F`，并可在匹配项之间跳转（`F3` / `Shift+F3`）。
- **Follow**——日志会自动滚动到新行。`Space` 键可开关跟随。若你向上滚动，跟随会暂停，并出现一个跳到底部的按钮。
- **Export**——将可见行保存到文件。

**何时使用。** 当你需要细节时：某个特定账号究竟发生了什么、按什么顺序发生。

![带事件日志的 Logs 界面](../images/logs-screen.png)

## 4.10. Layouts 界面

**用途。** 使用预设布局在一台或多台显示器上排列 CS2 窗口。

**位置。** 侧边栏的第七个部分（`Ctrl+7`）。

**关键概念：**

- **Preset**——已保存的窗口排列。
- **Slot**——显示器上的一块矩形区域，用于放置一个窗口。
- **Snap**——将运行中的窗口排入各 slot 的命令。

**主要区域：**

- **左侧**——已保存 preset 的列表。
- **右侧**——展示你的显示器的画布，你在其上放置 slot。
- **底部**——绑定表：哪个 slot 对应哪个账号或角色。

**如何使用。**
1. 用 **New Preset** 按钮创建一个 preset。
2. 在画布上放置 slot。
3. 设定哪个账号进入哪个 slot。
4. 点击 **Apply** 或 **Snap windows**——应用会将运行中的 CS2 窗口排入所定义的位置。

> **安全网。** 排列之前，应用会记住当前的窗口位置。**Revert layout** 按钮可在一分钟内恢复之前的位置。

![带显示器画布的 Layouts 界面](../images/layouts-screen.png)

## 4.11. Sandboxes 界面

**用途。** 管理 sandbox——运行 Steam 客户端的隔离环境。

**位置。** 侧边栏的第八个部分（`Ctrl+8`）。

**什么是 sandbox。** sandbox 是供单个 Steam 客户端使用的、独立且受保护的环境。不同 sandbox 中的账号从不重叠：它们不共享会话、文件或痕迹。一个账号绑定到一个 sandbox。

**何时使用。** 你在这里创建 sandbox 并观察其状态。多数情况下，添加账号时会自动分配 sandbox，因此你很少需要专门来此。

## 4.12. Settings 界面

**用途。** 按你的偏好调整应用。

**位置。** 侧边栏底部的 **Settings** 部分（`Ctrl+,`）。

**布局。** 左侧是设置分类列表；右侧是设置本身。更改会立即保存：每次之后都会出现简短的 **Saved** 通知。

**设置分类：**

| 分类 | 配置内容 |
|---|---|
| **General** | 随 Windows 启动、最小化到托盘、更新通道 |
| **Appearance** | 主题（**System / Dark / Light**）、密度、字体缩放、减少动效 |
| **Accounts** | 创建账号时的行为、已删除账号的保留 |
| **Workflows** | 重试策略、并发运行数上限 |
| **Sandboxes** | sandbox 文件夹、自动恢复 |
| **Monitoring** | 数据刷新率、警告阈值 |
| **Notifications** | 按严重级别的通知和声音 |
| **Layouts** | 默认布局、多显示器行为 |
| **Hotkeys** | 键盘快捷键——可重新分配 |
| **Advanced** | 日志级别、诊断、环境选择、恢复默认 |
| **About** | 应用版本、打开数据和日志文件夹的按钮 |

> **注意。** 某些设置（例如 sandbox 文件夹或环境）仅在重启后生效。此类设置旁会显示 “Requires restart” 徽标。

# 5. 核心工作流程

这是最重要的一节。它包含主要任务的完整分步说明。每一步都会描述你将看到什么，以及如何确认成功。

## 5.1. 添加单个账号

**目标。** 向应用添加一个新的 Steam 账号。

**你需要什么。** 账号的用户名和密码。如适用，还需一个 Steam Guard 验证码。

### 步骤 1 — 打开添加表单

前往 **Accounts** 界面，点击工具栏上的 **Add Account**。你也可以按 `Ctrl+N`。

**预期结果。** 打开一个含新账号字段的表单。

### 步骤 2 — 填写信息

填写各字段：

- **Login**——必填，必须唯一。
- **Password**——必填。
- **Steam Guard secret**——如果你有的话，填 Steam Guard 验证码（可选）。
- **Nickname**——可选；可能在首次登录时自动获取。
- **Tags**——用于分组的可选标签。
- **Sandbox binding**——选择 **Auto-assign**、某个具体 sandbox 或 **None**。
- **Workflow**——启动方案，如果你想立即分配的话。

**预期结果。** 如果用户名已被占用，该字段会被红色高亮并附带说明。弱密码会被琥珀色高亮——这是一个警告，并不阻止保存。

### 步骤 3 — 保存账号

点击表单中的保存按钮。

**预期结果。** 表单关闭，新账号以 **Draft** 状态出现在表格中；若已绑定 sandbox，则处于可启动状态。

**成功的标志。** 账号出现在 **Accounts** 界面的表格中。

### 提示

- 如果你在表单中启用 **Validate immediately**，应用会在后台检查用户名，并以通知形式显示结果。
- 账号要可启动，必须绑定到一个 sandbox。最简单的选择是 **Auto-assign**。

### 常见错误及修复方法

- **“Login already in use.”** 该用户名在应用中已存在。检查你的账号列表——你可能已经添加过它了。
- **忘记 sandbox。** 没有 sandbox 的账号无法启动。稍后通过右键菜单 → **Bind sandbox** 绑定一个。

![添加账号表单](../images/accounts-add-form.png)

## 5.2. 从文件导入账号列表

**目标。** 从文件一次性快速添加许多账号。

**你需要什么。** 一个含账号列表的文件（TXT、CSV 或 TSV）。最简单的 TXT 行格式是 `login:password`（你也可以使用 `login:password:steamguard:nickname`）。

### 步骤 1 — 启动导入向导

在 **Accounts** 界面，点击 **Import** 按钮旁的箭头并选择一个来源——例如 **From file…**。你也可以按 `Ctrl+I`。

**预期结果。** 打开一个分步导入向导。

### 步骤 2 — 选择来源以及 sandbox 的分配方式

用 **Browse…** 按钮指向文件。在底部，选择如何分配 sandbox：

- **Auto-assign (round-robin)**——循环分配（推荐）；
- **Bind to specific sandbox**——将它们全部绑定到一个 sandbox；
- **Leave unbound**——不为它们绑定 sandbox。

点击 Next。

### 步骤 3 — 检查数据的识别情况

向导会将文件的前几行以表格形式展示。确认数据被正确拆分为各列。如果分隔符识别错误，请手动设置。

**预期结果。** 在预览中，用户名和密码各在其自己的列中。

### 步骤 4 — 映射字段

将列标题拖到所需单元格上：**Login**、**Password**、**SteamGuard**、**Nickname**。

### 步骤 5 — 检查各行是否有效

向导会标记每一行：✓ 有效、⚠ 警告、✕ 错误。含错误的行可就地修复或跳过。

**预期结果。** 你会看到将添加多少个账号、有多少重复、有多少存在错误。

### 步骤 6 — 确认导入

点击 **Import N accounts**。

**预期结果。** 出现带逐行状态的进度条。完成后，账号会出现在表格中。

**成功的标志。** 表格中的账号数量已按导入数量增加。

### 如何取消并恢复

如果你在导入进行中取消，应用会提出回滚已添加的这一批。确认回滚即可返回到原始状态。

![导入向导，行校验步骤](../images/import-wizard-validation.png)

## 5.3. 启动多个账号

**目标。** 同时启动若干个账号。

**你需要什么。** 已添加并已绑定 sandbox 的账号。

### 步骤 1 — 选择账号

在 **Accounts** 界面，在第一列勾选你想要的账号。若要选中所有可见项，按 `Ctrl+A`。

**预期结果。** 工具栏切换到批量模式，并显示已选中多少行，例如 `12 selected`。

### 步骤 2 — 启动所选账号

点击批量工具栏上的 **Start**。你也可以按 `Ctrl+R`。

**预期结果。** 所选账号的状态变为 **Starting**。应用会准备每个账号并开始启动。启动分批进行，以免计算机过载。

### 步骤 3 — 等待启动

关注状态列。等待账号转入 **Running** 状态。

**预期结果。** 已启动的账号显示 **Running**，旁边带有一个运行时长计数器。

**成功的标志。** 所有所选账号均显示 **Running**。状态栏中的活动计数已增加。

### 提示

- 你不必一次性启动每个账号。先从一小批开始，确认一切稳定，然后再增加。
- 若要启动单个账号：选中一行并点击 **Start**，或使用右侧详情窗格中的 **Start** 按钮。

### 常见错误及恢复

- **某账号在 Starting 停留过久。** 登录可能较慢。请等待；若状态变为 **Error**，使用 **Retry** 按钮。
- **部分账号未能启动。** 批量启动后，汇总会显示成功和失败的数量。点击 **Filter to failed** 以仅处理那些账号。

![账号的批量启动，Starting/Running 状态](../images/accounts-bulk-start.png)

## 5.4. 停止所有正在运行的账号

**目标。** 干净地关闭所有活动账号。

### 步骤 1 — 选择账号

选中正在运行的账号。若要选中所有可见项，按 `Ctrl+A`。

### 步骤 2 — 停止它们

点击批量工具栏上的 **Stop**，或按 `Ctrl+.`（Ctrl 加句点）。

**预期结果。** 应用会干净地关闭每个账号。状态变为 **Stopped**。如果某账号无响应，一段时间后应用会强制关闭它。

**成功的标志。** 所有账号均显示 **Stopped**。状态栏中的活动计数已减少。

### 提示

- **Stop** 是一次优雅的关闭。应用会先尝试正确地关闭客户端。
- 如果某账号正在对局中，先完成游戏内的操作，再停止它。

## 5.5. 创建队伍并排队

**目标。** 组建一个由若干账号构成的队伍，让它们一起排队匹配。

**你需要什么。** 若干已登录且正在运行（**Running**）的账号。

### 步骤 1 — 创建一个队伍

前往 **Matchmaking** 界面，点击 **Create Party**。你也可以按 `Ctrl+N`。

**预期结果。** 打开一个窗口，你可以在其中向队伍添加账号并为其命名。

### 步骤 2 — 添加成员并保存

向队伍添加 2 到 5 个账号，设定名称，然后保存。

**预期结果。** 新队伍出现在左侧列表中。

### 步骤 3 — 检查 quorum

选中队伍并查看右侧的成员。确认队伍处于 **Quorum** 状态——即所有成员均已登录并就绪。

**预期结果。** 队伍会显示 **✓ Quorum** 徽标。如果某成员存在问题（例如登录缓慢），它会作为单独一行显示。

### 步骤 4 — 让队伍排队

对所选队伍点击 **Queue**（或 `Ctrl+Q`）。若要一次性让所有队伍排队，使用工具栏上的 **Queue All**。

**预期结果。** 排队前，应用会执行其检查。随后所有成员进入队列，并显示其位置和网络延迟。

**成功的标志。** 成员处于排队状态，并有一个等待时长计数器在计时。

### 提示

- 排队前，在工具栏上选择区域和模式（例如 `EU` 和 `Premier`）。
- 如果队伍进入 **Desync** 状态，使用 **Re-sync** 操作暂停队列并等待达到一致状态。

![带成员位置、正在排队的队伍](../images/matchmaking-party-queue.png)

## 5.6. 找到对局时会发生什么

**目标。** 了解在找到对局的那一刻应用会做什么。

**你需要什么。** 一个正在排队的队伍。

### 对局接受是自动的

当 Steam 找到对局时，队伍会显示一个醒目的 **MATCH FOUND** 横幅。**你无需点击任何东西**——应用会在给定的时间窗口内为所有队伍成员确认准备就绪。无需你采取任何行动。

**预期结果。** 队伍成员会自动接受对局；其状态变为 **✓ Accepted**。

**成功的标志。** 所有成员均显示 **Accepted**，对局开始。

> **提示。** 想不盯着屏幕也能知道找到了对局？在 **Settings → Notifications** 中为 **Match found** 启用声音提醒。接受仍然是自动进行的——声音只是为了让你及时知情。

### 队伍 desync 时该怎么办

有时无法为所有人确认对局——例如某成员掉出了队列。此时队伍会进入 **Desync** 状态。使用 **Re-sync** 操作，如有需要，用 **Drop member** 移除有问题的成员，然后让其余成员重新排队。

![Match Found 横幅](../images/matchmaking-match-found.png)

## 5.7. 崩溃或应用重启后的恢复

**目标。** 在客户端崩溃后，或在应用被关闭并再次打开后，将农场恢复到可用状态。

**你需要什么。** 无需额外准备——恢复大多会自动进行。

### 会自动发生什么

- **客户端崩溃后。** 如果 Steam 或 CS2 意外关闭，应用会察觉到，将账号标记为 **Crashed** 状态，并显示一个带 **Restart** 按钮的通知。恢复往往会在几秒内自行完成。
- **应用重启后。** 启动时，应用会查找上一会话遗留的 Steam 与 CS2 进程，并将它们重新纳入管理。其间，状态栏会出现 **Recovering** 指示。被重新接管的账号会短暂标记为 “Reattached”。

### 需手动做什么

1. 打开 **Dashboard** 并查看 **Failures & Crashes** 表格。
2. 对于崩溃的账号，在通知中、账号行中或详情窗格中点击 **Restart**。
3. 如果应用在通知中心报告 **Orphan process**，选择 **Adopt** 或 **Kill**。

**成功的标志。** 账号重新处于 **Running** 状态，红色的崩溃标记消失，状态栏中没有活动的 **Recovering** 指示。

### 提示

- 崩溃后不要立即手动重启一切——先给自动恢复几秒钟时间。
- 如果崩溃反复出现，打开 **Monitoring** 查看负载：你运行的账号可能超出了这台计算机的承受能力。

![状态栏中的 Recovering 指示](../images/status-recovering.png)

# 6. 常见任务（「我想要…」）

对常见目标的简短回答。完整说明请按链接前往第 5 节。

## 「我想添加新账号」

- **何时需要。** 你有新的 Steam 账号。
- **该怎么做。** 添加单个账号，使用 **Accounts** 界面上的 **Add Account** 按钮。一次添加许多个，使用 **Import** 按钮和导入向导。

- **何时需要。** Steam 已在运行，你需要启动游戏。

- **会发生什么。** 成员进入队列；你会看到其位置和等待时间。

## 「我想停止所有正在运行的会话」

- **何时需要。** 到了收尾的时候。
- **该怎么做。** 选中账号（`Ctrl+A`）并点击 **Stop**。
- **会发生什么。** 应用会干净地关闭客户端，状态变为 **Stopped**。
- 更多：[5.4](#54-停止所有正在运行的账号)。

## 「我想在崩溃后恢复」

- **何时需要。** 客户端崩溃了，或应用被重启了。
- **该怎么做。** 给自动恢复几秒钟；如有需要，对崩溃的账号点击 **Restart**。
- **会发生什么。** 应用会让账号重新投入工作。
- 更多：[5.7](#57-崩溃或应用重启后的恢复)。

## 「我想在屏幕上排列窗口」

- **何时需要。** 你想在显示器上整齐地摆放 CS2 窗口。
- **该怎么做。** 在 **Layouts** 界面创建一个 preset，然后点击 **Apply** / **Snap windows**。
- **会发生什么。** 运行中的窗口会移动到所定义的位置。

# 7. 功能参考

本节按功能的用途、位置和特点逐一介绍各项功能。

## 7.1. 账号搜索与筛选

**用途。** 在庞大的列表中快速找到你需要的账号。

**位置。** **Accounts** 界面工具栏：搜索框和 **Filters** 按钮。

**如何使用。**
- 在搜索框中键入（`Ctrl+F`）。你可以按各部分搜索：`login:alex`、`status:running`、`rank:>=gold`、`tag:prime`。
- 点击 **Filters**（在本界面按 `Ctrl+K` 会打开筛选窗口），按状态、段位、sandbox、工作流程或标签设置条件，并将该组合保存为 preset。

**预期行为。** 表格会立即只显示匹配的账号。活动筛选会以一排 chip 的形式显示在工具栏下方。

**提示。** 将常用的条件组合保存为 preset——它们可从工具栏的下拉菜单中获取。

## 7.2. 分组与列设置

**用途。** 将表格整理成适合你任务的样子。

**位置。** **Accounts** 界面工具栏：**Density**、**Columns** 和 **Group** 按钮。

**如何使用。**
- **Group** 允许你按状态、工作流程、sandbox、标签或段位对账号分组。分组会显示计数，例如 `Running (24)`。
- **Columns**——可见列的组合。提供内置组合：**Operational**、**Identity**、**Audit**、**Compact**。你也可以保存自己的组合。
- **Density**——行高（更紧凑或更宽松）。

## 7.3. 账号右键菜单

**用途。** 快速访问某账号的每一项操作。

**位置。** 右键单击某个账号行。

**有哪些可用项。** 编辑、复制用户名或 Steam ID、启动/停止/重启、绑定和解绑 sandbox、分配工作流程、重新认证（**Re-auth**）、探测登录（**Probe login now**）、处理标签、导出、克隆和删除。

## 7.4. 批量操作

**用途。** 一次对多个账号执行同一操作。

**位置。** 处于选择模式（至少勾选一行时）的 **Accounts** 界面工具栏。

**如何使用。** 勾选账号，然后点击你需要的按钮：**Start**、**Stop**、**Restart**、**Bind sandbox**、**Workflow…**、**Tag…**、**Export** 或 **Delete**。

**预期行为。** 出现一个带逐账号进度视图的窗口。你可以在操作进行时取消它。

**限制。** 删除五个或更多账号时，应用会要求你键入单词 `DELETE` 进行确认。

## 7.5. 导出账号

**用途。** 将账号数据保存到文件。

**位置。** 工具栏或右键菜单中的 **Export** 按钮。

**如何使用。** 选择一种格式：**TXT**（login:password）、**CSV**（所有字段）或 **JSON**（完整记录）。

> **警告。** 导出密码需要单独的同意——应用会要求你勾选一个复选框。请谨慎处理此类文件。

## 7.6. 克隆账号

**用途。** 快速创建某账号的副本作为起点。

**位置。** 行右键菜单 → **Clone…**。

**预期行为。** 打开一个已预填字段的表单（用户名变为 `original_copy`），但 Steam Guard 验证码和 sandbox 绑定除外——这两项由你重新设置。

## 7.7. Workflows：启动、暂停、停止

**用途。** 管理自动方案。

**位置。** **Workflows** 界面。

**如何使用。**

| 操作 | 作用 | 是否要求确认？ |
|---|---|---|
| **Start** | 为所选账号运行方案 | 启动超过 10 个账号时 |
| **Pause** | 在当前步骤后温和地暂停 | 否 |
| **Resume** | 从当前点继续 | 否 |
| **Stop** | 结束方案并进行清理 | 是 |
| **Restart** | 停止并从头重新开始 | 是（针对批量操作） |
| **Skip step** | 将当前步骤标记为完成并继续 | 是 |
| **Retry now** | 立即重试当前步骤 | 否 |

**提示。** 详情窗格中的 **State Machine** 标签页会清晰展示方案处于哪一步。

## 7.8. 绑定到 sandbox

**用途。** 为账号预留一个隔离环境，没有它账号便无法启动。

**位置。** 右键菜单 → **Bind sandbox…**，或 **Bind sandbox** 批量操作。

**如何使用。** 选择一种方式：round-robin、优先填充空闲的，或某个具体 sandbox。

**限制。** 一个账号，一个 sandbox。如果所选 sandbox 已在使用中，应用会提出将它从之前的账号释放。

## 7.9. 窗口布局

**用途。** 使用预设布局排列 CS2 窗口。

**位置。** **Layouts** 界面。

**如何使用。** 创建一个 preset，在显示器画布上放置 slot，设置绑定，然后点击 **Apply**。

**提示。** 若某个布局不理想，**Revert layout** 按钮可在一分钟内恢复之前的窗口位置。

## 7.10. 通知中心

**用途。** 集中放置所有应用通知的地方。

**位置。** 顶部栏中的通知徽标，或 `Ctrl+Shift+N`。

**如何使用。** 面板在右侧打开。在 **All**、**Errors**、**Warnings** 和 **Info** 标签页之间切换。对每条条目，你可以前往来源、重试或忽略。**Clear all** 按钮会清空列表。

**限制。** 只保留最近 200 条；更早的会被移除。

# 8. 状态与指示器

每种状态都有一个颜色、一个符号和一个标签。以下是每种状态的含义，以及你是否需要采取行动。

| 状态 | 符号 | 含义 | 是否需要行动 |
|---|---|---|---|
| **OK / Success** | ✓（绿色） | 账号在线，登录成功 | 否 |
| **Running** | ▶（蓝色） | 账号或工作流程正在运行 | 否 |
| **Starting** | ◐（紫色） | 正在启动，一种过渡状态 | 等待其完成 |
| **Queued** | ⏱（灰色） | 在队列中等待 | 否 |
| **Stopped** | ■（灰色） | 已停止，空闲 | 可选——你可以启动它 |
| **Paused** | ⏸（琥珀色） | 方案已暂停 | 点击 **Resume** 继续 |
| **Warning** | △（琥珀色） | 一个非关键的异常 | 检查详情；通常你可以继续 |
| **Error** | ✕（红色） | 一个可恢复的故障 | 点击 **Retry** 或排查原因 |
| **Crashed** | ☠（深红，脉动） | 进程意外退出 | 点击 **Restart** |
| **Match Found** | ◎（绿色，脉动） | 找到了一场 CS2 对局 | 无——应用会自动确认准备就绪 |
| **Desync** | ⛓（橙色） | 队伍成员不同步 | 运行 **Re-sync** |
| **Info** | ⓘ（蓝色） | 一条中性消息 | 否 |

**其他指示器：**

- **Recovering**——应用启动期间状态栏中的蓝色指示：上一会话的进程正被重新纳入管理。等待其完成。
- **Reattached**——账号行上的临时标记：进程在重启后被成功接管。
- **Frozen at HH:mm:ss**——在 **Monitoring** 界面上，表示数据显示已被冻结（不在 **Live** 模式）。要恢复实时数据，切换到 **Live** 或关闭 **Freeze**。

**如何查看详情。** 将鼠标悬停在状态符号上可获得一个工具提示：该状态已持续多久、账号处于哪一步、上一个事件是什么。

# 9. 通知

应用以三种方式报告事件：**toast**（在角落弹出并消失）、**状态栏**（底部的持久汇总）和**内联横幅**（与特定界面绑定）。

## Toast

它们出现在右下角。

| 通知 | 为何出现 | 含义 | 该怎么做 | 能否忽略 |
|---|---|---|---|---|
| **Saved** | 你更改了某项设置 | 更改已保存 | 无 | 是，会自行消失 |
| 操作成功（绿色） | 某项操作成功完成 | 一切正常 | 无 | 是，约 5 秒后消失 |
| 警告（琥珀色） | 察觉到一个非关键异常 | 值得看看 | 可选地查看详情 | 通常是，约 10 秒后消失 |
| 错误（红色） | 某项操作失败 | 需要采取行动 | 点击 **View** 或 **Retry** | 否，在被忽略前一直保留 |
| 崩溃 | 某个客户端意外关闭 | 某个账号崩溃了 | 点击 **Restart** 或打开转储 | 否，在被确认前一直保留 |

**值得了解。**
- 将鼠标悬停在通知上会停止自动消失计时器——你可以从容阅读它。
- 相同的通知会合并为一条并带计数，例如 `… failed (×4)`。

## 状态栏

在状态栏的右侧，会显示最重要的未读通知，例如 `● 3 errors`。点击它可打开通知中心。

## 内联横幅

它们出现在某界面的顶部，并整体适用于该界面。示例：`⚠ Steam network degraded — 12 accounts retrying login`。如果横幅不是阻塞性的，可用 **Dismiss** 按钮关闭。阻塞性横幅（例如某项服务不可用时）会一直保留，直到问题解决。

## 声音提醒

声音默认关闭。你可以在 **Settings → Notifications** 中为特定事件（例如 **Match found** 或 **Crash**）启用它。为 **Match found** 设置声音，便于你不盯着屏幕也能知道找到了对局——对局的接受本身是自动进行的。

# 10. 错误与故障排除

运行农场时出现错误是家常便饭，应用会帮你解决它们。以下是以“问题 → 可能原因 → 解决方案 → 预期结果”格式列出的常见情形。

## 无法激活许可

**问题。** 输入密钥时，应用不让你继续。

| 消息 | 可能原因 | 解决方案 |
|---|---|---|
| “License key invalid” | 密钥输入时有笔误 | 检查拼写。用 **Paste from clipboard** 粘贴密钥更省事 |
| “Used on max devices” | 许可已在最多数量的设备上使用 | 在另一台设备上释放许可，然后重试。**Manage devices** 按钮通向设备管理 |
| “Cannot reach license server” | 无法连接许可服务器 | 检查你的网络连接并点击 **Retry** |

**预期结果。** 密钥正确且能连接服务器时，激活窗口关闭，**Dashboard** 打开。

## 某个账号无法启动

**问题。** 你点击了 **Start**，但账号未转入 **Running**。

- **可能原因。** 账号未绑定到 sandbox。
  **解决方案。** 打开账号的右键菜单 → **Bind sandbox…** 并分配一个 sandbox。
- **可能原因。** 需要重新认证（登录信息过期）；行旁有 “Reauth required” 标记。
  **解决方案。** 右键菜单 → **Re-auth (Steam Guard)**。
- **可能原因。** Steam 暂时对登录进行了速率限制。
  **解决方案。** 等待约一分钟并点击 **Retry**。

**预期结果。** 状态由 **Starting → Running**。

## Steam 长时间停留在 Waiting/Starting

**问题。** 账号卡在登录阶段。

- **可能原因。** 登录缓慢或 Steam 网络临时出现问题。
  **解决方案。** 稍等片刻。若出现 **Error** 状态，点击 **Retry**。如果 Steam 网络不稳定，顶部会出现一个警告横幅——等待它恢复。

**预期结果。** 账号登录并转入 **Running**。

## 某个客户端崩溃了

**问题。** 账号得到了 **Crashed** 状态。

- **可能原因。** CS2 或 Steam 客户端意外退出。
  **解决方案。** 在出现的通知中点击 **Restart**。恢复往往已在自动进行。崩溃详情在 **Monitoring** 界面的 **Crashes & Warnings** 信息流中。

**预期结果。** 账号重启并返回 **Running**。

## 某个队伍进入了 Desync

**问题。** 队伍处于 **Desync** 状态——成员处于不一致状态。

- **可能原因。** 一名成员接受了对局而另一名未及时接受，或有人掉出了队列。
  **解决方案。** 点击 **Re-sync** 暂停队列并等待达到一致。如果某个账号在捣乱，用 **Drop member** 移除它，然后让其余成员重新排队。

**预期结果。** 队伍返回 **Quorum** 状态，可再次排队。

## 批量启动带着错误结束

**问题。** 批量 **Start** 后，部分账号未能启动。

- **解决方案。** 在汇总中点击 **Filter to failed**——表格会只显示有问题的账号。按上面的原因逐一解决，然后再次启动。

**预期结果。** 原因解决后，再次 **Start** 会将账号转入 **Running**。

## 某个界面的数据无法加载

**问题。** 界面内容处出现的是一个横幅，或提示某项服务不可用。

- **可能原因。** 某项后台服务暂时不可用。
  **解决方案。** 点击 **Retry**。如果无济于事，点击 **Open logs** 查看详情，或重启应用。

**预期结果。** 界面加载并显示当前数据。

## 应用报告 Orphan process

**问题。** 通知中心里出现类似 “Orphan process … — Adopt or Kill?” 的消息。

- **可能原因。** 上一会话遗留了一个进程，无法自动绑定到某个账号。
  **解决方案。** 如果需要该进程，选择 **Adopt**（纳入管理）；否则选择 **Kill**（结束它）。

**预期结果。** 进程列表恢复整洁。

## 计算机变慢且崩溃增多

**问题。** 总体不稳定，故障频繁。

- **可能原因。** 运行的账号超出了计算机的承受能力。
  **解决方案。** 打开 **Monitoring** 并查看 **CPU** 和 **RAM**。如果数值接近上限，用 **Stop** 停止一些账号。

**预期结果。** 负载下降，运行趋于稳定。

> **错误代码。** 错误详情包含一个简短代码，如 `[E-1042]`。你可以复制它，在联系支持时使用。完整的代码参考可通过 **Help → Error reference** 获取。

# 11. 最佳实践

## 准备账号

- 通过 **Import** 以列表方式添加账号——更快且更少笔误。
- 除非你需要特定绑定，否则将 sandbox 分配保留为 **Auto-assign**。
- 使用 **Tags** 对账号分组并快速筛选。

## 启动大量账号

- 分批启动：先从一小组开始，确认稳定后再增加。
- 让 **Dashboard** 或 **Monitoring** 保持打开，以实时观察负载。
- 争取同时运行推荐的 4–10 个 CS2 账号；强力 PC 上可以运行更多，较弱的机器上则少一些。

## 使用布局

- 事先为不同场合准备好几个 preset（例如 “4-stack”、“single focused”）。
- 某个布局出错后，趁一分钟的撤销窗口仍有效，立即使用 **Revert layout**。

## 安全地停止

- 用 **Stop** 按钮（一次优雅的关闭）停止账号，而不是手动关闭窗口。
- 退出应用前，先停止活动账号。如果你在方案运行时试图关闭应用，它会向你发出警告。

## 避免中断

- 排队前，确保队伍处于 **Quorum** 状态。
- 留意有关 Steam 网络状态的横幅——网络不稳定时，最好等一等。

## 保持稳定运行

- 定期查看 **Dashboard**——它能在几秒内展示总体状态。
- 将同时运行的账号数量控制在你计算机的承受范围内。
- 在亲自动手干预之前，先让自动恢复运作几秒钟。

# 12. 常见问题

**为什么我无法启动某个账号？**
最可能是账号未绑定到 sandbox——没有它便无法启动。通过右键菜单 → **Bind sandbox…** 绑定一个。启动也可能因需要重新认证（“Reauth required” 标记）而受阻——那种情况下运行 **Re-auth**。

**为什么 Steam 长时间处于等待状态？**
这通常是登录缓慢或 Steam 网络临时延迟。稍等片刻。若出现 **Error** 状态，点击 **Retry**。

**我如何重启一个工作流程？**
选中你需要的账号或 instance，点击 **Restart**（或 `Ctrl+Shift+R`）。对于批量操作，应用会要求确认。

**如果应用关闭会发生什么？**
你的账号和设置会被保存。下次启动时，应用会尝试将上一会话的进程重新纳入管理——状态栏会出现 **Recovering** 指示。如果关闭时有方案在活动，应用会预先向你发出警告。

**我如何知道一切正常？**
查看底部的状态栏和 **Dashboard**。正常运行的标志：账号处于 **Running** 状态，**Errors** 卡片或 **Failures & Crashes** 表格中没有红色标记，且 **CPU** 和 **RAM** 负载处于正常范围。

**我的密码存储在哪里？**
只在你的计算机上。它们通过 Windows 内置保护加密，从不以明文保存，也从不发送到任何地方。

**FarmPanel 会替我游玩吗？**
不会。它不是机器人，也不是自动搬砖工具。应用管理的是启动、监控、大厅组建和恢复，而所有游戏内操作都由你完成。

**我每次都要输入许可密钥吗？**
不用。密钥只在首次激活时输入一次。此后应用会直接打开到 **Dashboard**。

**如果我忘了按钮在哪里，如何快速找到某个操作？**
按 `Ctrl+K` 打开命令面板。开始键入某个操作、界面或账号用户名的名称，然后从列表中选取你需要的那一项。

**我可以把 monitoring 移到第二台显示器吗？**
可以。在 **Monitoring** 界面点击分离按钮——该界面会作为一个单独窗口打开，你可以把它放到第二台显示器上。它的位置会被记住。

**我如何将设置恢复为默认？**
在 **Settings → Advanced** 中有 **Reset to defaults**。为防止误点，应用会要求你键入文本进行确认。
